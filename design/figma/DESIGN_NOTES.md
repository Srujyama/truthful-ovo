# Truthful · working-ledger design

## Direction and scope

The user rejected the earlier sage-tinted interface and requested a complete UI redesign. The Figma reconstruction now uses the same replacement direction as the app: neutral paper surfaces, graphite typography, a restrained forest action color and Public Sans. The [native file](https://www.figma.com/design/8j4pwtsGDI4seljHPNeUkI) contains 17 editable screens (14 desktop and 3 mobile), seven product boards, 12 real component nodes, 13 color variables and 20 review-note overlays and one mobile navigation overlay. The new root app system is recorded in [DESIGN.md](../../DESIGN.md); this file describes the native reconstruction and its limits.

## Applied philosophy

[Apple and Ramp principles](DESIGN_PHILOSOPHY.md) guide the refinement: begin with the finance task, make the next action clear, and reduce the amount of interface a person must process. The native prototype opens on the portfolio. The account selector is quieter, vendor rows are compact, the outstanding amount leads its case, and mobile approval carries the exact selected commitment reference. The dedicated verification state exposes signed-record detail at the point of review.

## Structure

Functional page titles replace repeated promotional slogans. The rail is a white navigation surface with an explicit selected row; its former brand-promise block is removed. Source documents lead the evidence input, while the no-result panel carries one instruction. The portfolio uses a vendor register beside a financial case; money states remain distinct. A ruled relationship structure explicitly names source support, partial invoice fulfillment and the proposed action’s preservation of original terms. Race setup places its real supplied program, actors and steps on one principal white working surface with a column divider and row rules; the run control sits beside scenario and budget. Its particular native example is the approved Pipeline portfolio-copy scenario rather than the app’s default authored credit-allocation family. The existing screen map supplies the entry and truth boundaries.

Approval, scope and effect remain separate steps. The receipt uses one compact ruled review surface rather than oversized parallel cards. Its four outcome facts state that a preserve-original-terms action creates no applied savings. The selected-case handoff remains an explicitly labeled concept. No design control executes a financial action.

## Native system

The palette is paper `#ffffff`, canvas `#f7f8fa`, graphite ink `#20252b`, muted text `#626b75`, rules `#e3e7eb`, forest `#176448` and selected wash `#edf5f0`. Warnings use `#8a5b17` on `#fff5e4`; refusals use `#b23d37` on `#fcf0ef`. State colors always retain a written label. The historical variable name `sage-rail` remains as a compatible alias for neutral canvas, not a sage-colored design decision.

All 653 screen text layers are editable Public Sans at 12px or larger. Regular, Medium, SemiBold and Bold are real loaded native faces, with no missing fonts found by the actual API. Desktop page titles are 28px; mobile titles are 24px. Operational copy is 12–17px. Financial amounts carry tabular values with local hierarchy, while the story boards use 52px introductory and 36px section headings. The Public Sans WOFF2 and OFL license are bundled under `assets/`; the official variable TTF was installed locally for native rendering.

Controls and document insets use a 6px radius; major grouped surfaces use 10px; small named states use 4px. They are flat surfaces with fine rules, not elevated cards. Desktop frames are 1440 × 960 and mobile frames 390 × 844. Mobile headers consistently expose a visible Navigation control. It opens an editable menu with three actual prototype destinations and a close return. The 520 × 450 review notes use a single descriptive heading, explanation, explicit static-design boundary and return control.

## Interaction limits

The native prototype uses review-state navigation. Same-screen actions open clearly labeled notes rather than pretending to approve, execute, edit a source or transfer money. Keyboard tab behavior and reduced-motion support belong to the working web app and HTML companion; native component specimens do not establish interactive hover states. All financial examples and local effects remain synthetic. No video, external submission, billing or file-sharing change is part of this redesign.
