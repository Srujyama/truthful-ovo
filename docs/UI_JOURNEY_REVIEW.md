# UI journey completion evidence

This pass preserves the Apple/Ramp-inspired working-ledger direction and improves the actual finance task across the React application and editable Figma file. It adds no external transaction, live model, production identity, video or public deployment.

| Requirement | Implementation | Acceptance evidence |
| --- | --- | --- |
| Put the selected financial task first | Compact portfolio totals and register; workspace administration under Workspace options; visible selected-case next action | Browser journey checks selected record begins above 400px and desktop next action fits the first viewport; desktop/mobile/intermediate captures inspected |
| Give imported commitments their own review path | Original-action proposal and review tied to the exact commitment; explicit case-specific empty decision state | Real reducer integration plus browser import of Northstar Research / NS-UI-2026 through proposal, approver approval and executor recording |
| Keep pending work ahead of completed work | Prefer fresh pending actions, then stale pending actions, then recorded fallback | Mixed-state reducer regression: recorded → pending → source revision → stale pending → refreshed proposal |
| Inspect evidence without losing the action | Exact bound revision openers; return to the originating review and restore opener focus | Browser opens Pipeline promise revision 6, returns to the same action, and checks focus |
| Keep historical knowledge isolated | Resolve selected records through the current snapshot graph; close unavailable source detail | Browser selects an October 28 source, moves Known by to October 27, and verifies source text and graph entry are absent |
| Explain role boundaries before rejected writes | Command-specific disabled reasons for proposal, approval, recording, source/ledger/policy changes and reset; import preflight checks the actual generated batch | UI role checks plus reducer role-matrix tests; analyst cannot approve, approver cannot record; existing-record navigation remains allowed for every role |
| Distinguish claim approval from portfolio import | Specific evidence approval reasons; independent import preview; no-command tracked-record navigation; exact revalidation before writes | Real report/import fixtures cover changed terms, scheduled/fully applied promises, unsupported replies, role changes, busy/connecting states and conflicting records |
| Explain empty and blocked states | Truthful empty ledger, selected-case empty queue and adjacent next-step copy | Browser checks Parcel's empty ledger and decision state; report fixtures verify blocked claim reasons |
| Keep mobile usable | Selected commitment and action pickers; current next action before supporting ledger; keyboard-trapped navigation with inert background, Escape/backdrop close and focus restoration | Browser checks 390px, 900px and 1440px layouts; mobile CTA visibility and no document overflow |
| Recover from stalled initialization | Health, session and workspace requests share the initialization abort signal | Actual hook transport tests stall session/workspace requests and verify browser fallback without replacing server data |
| Preserve existing product capabilities | Financial reducers unchanged; existing evidence, assurance, guided-case, exploration and signed-authority browser checks updated for the new disclosures | Integrated application checks and retained browser workflow reports |
| Keep native Figma coherent | Original 17 screen/master identities retained; updated finance hierarchy, guided-demo scope, exact source handles and review notes; recorded root inventory protects owned updates | Native record, system manifest, target/ownership regression tests, API gates and independently reviewed native exports |

The reusable browser journey is [browser-ui-journey-check.js](../scripts/browser-ui-journey-check.js). It passed 32 assertions in browser-local mode and 32 in the SQLite mode. A separate service-error browser check passes four assertions for reset failure, unchanged financial records, handled errors and explicit retry. The six retained workflow scripts pass 99 assertions, for 167 browser assertions across this pass. Logs and captured PNGs live under `output/playwright/ui-next-*`; these are local verification artifacts, not a video or a public release.
